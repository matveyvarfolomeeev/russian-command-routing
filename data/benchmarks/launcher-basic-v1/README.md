# Launcher-basic-v1: обычные запросы пользователя

Подготовлен 3 октября 2026 года как отдельный базовый набор рядом с
[launcher-v1](../launcher-v1/README.md). Всего **400 авторских текстовых запросов**:
200 на реальном каталоге и 200 на полностью вымышленном. В каждом наборе
50 validation и 150 test; train и аудио отсутствуют.

иконки или секреты. Живая база при подготовке не изменялась и не перечитывалась.

Цели, семейства `p01`–`p50`, количество перефразов и разбиения соответствуют
launcher-v1. В каждом наборе 50 целей: 35 приложений, 10 папок и 5 файлов.

## Какие запросы включены

Пользователь называет программу, её привычное разговорное имя или понятное
назначение. Включены нормальные сокращения, склонения, несколько умеренных
опечаток и обычные уточнения нужной версии. В test есть простые запросы
с точным названием: их качество также нужно измерять.

Примеры реального набора:

- «Открой телеграм» → Telegram.
- «Покажи папку со скачанными файлами» → Загрузки.
- «Мне нужна программа Microsoft для презентаций» → PowerPoint.
- «Открой обычный блокнот Windows» → Notepad.
- «Открой Spotfy» → Spotify.

Примеры вымышленного набора:

- «Открой Северник» → Северник.
- «Мне нужен редактор документов с оглавлением» → Буквоград.
- «Мне нужны учебные карточки для повторения слов по расписанию» → Мнемолист.
- «Мне нужна панель управления локальными контейнерами» → Кубодок.

Неправильная раскладка, смешение похожих букв разных алфавитов, отрицание
нескольких конкурентов и цепочки исправления выбора оставлены сложному набору.
Простые фразы из его validation тоже бывают обычными запросами пользователя:
их совпадения здесь допустимы и явно посчитаны в manifest.

Точная доля таких формулировок в реальном использовании неизвестна:
это авторская базовая проверка, а не выборка пользовательских логов.

## Ответы, формат и происхождение

В каждом примере одна однозначная цель из снимка; `expected_action` всегда
`open`, `expected_object_id` всегда заполнен. Если короткое имя неоднозначно,
использовано положительное уточнение: обычный блокнот, интерпретатор,
основное руководство, активный проект или обычный 32-битный PowerShell.
Запросы на уточнение, отказ и отсутствующие объекты добавляются позже.

Формат совместим с launcher-v1: `catalog.json`, `validation.jsonl`,
`test.jsonl`, `manifest.json`. Поля строки: `id`, `query`, `expected_action`,
`expected_object_id`, `input_type`, `group_id`, `tags`, `source`, `rationale`.
Модель получает только `query` и полный список `catalog.objects`.
Эталонные ID, обоснования, теги и группы ей не передаются.

В manifest зафиксированы хеши файлов, профиль `difficulty: basic`, контракт
`allowed_actions: ["open"]`, `require_unique_target: true`, `metric: top1_accuracy`.
Поле `comparison` хранит связь со сложным набором, его исходные хеши и число
совпадающих нормализованных запросов по разбиениям.

Все 400 сериализованных запросов и ID проверены авторским проходом по каталогам,
исправленные строки просмотрены повторно. В manifest указано
`annotation_review.status: author_reviewed`, `reviewed_rows: 200`,
`independent: false`. Независимой человеческой проверки и предсказаний моделей
при назначении ответов не было. Источник строк — `authored`.

## Разбиение и оценка

В каждом наборе 13 семейств validation и 37 test. Перефразы одной цели
не пересекают разбиения. Семейство сохраняет один split между реальным,
вымышленным, базовым и сложным наборами; совпадающий запрос также сохраняет
группу и split. Это позволяет настраивать метод на validation обоих профилей
без переноса той же цели или формулировки из validation в test.

Основная метрика — **top-1 accuracy**: точно совпавшие ID / все запросы
разбиения. Отказ, уточнение, неизвестный ID и сбой считаются ошибкой.
Результаты сообщайте отдельно для обычных и сложных запросов и для двух
каталогов. Совпадающие примеры не являются независимым подтверждением;
среднее по двум профилям не описывает частоту ошибок реального пользователя.

Настройки выбирайте на validation, после фиксации используйте test.
Эти данные не включайте в будущий train. Во время оценки объекты не открываются.

## Проверка

Из корня репозитория:

~~~powershell
.\.venv\Scripts\python.exe scripts\validate_benchmark.py data\benchmarks\launcher-basic-v1\synthetic artifacts\benchmarks\launcher-basic-v1\real
.\.venv\Scripts\python.exe scripts\validate_benchmark.py data\benchmarks\launcher-basic-v1\synthetic artifacts\benchmarks\launcher-basic-v1\real data\benchmarks\launcher-v1\synthetic artifacts\benchmarks\launcher-v1\real
~~~

Вторая команда проверяет четыре набора вместе, включая дубли и разбиения
между профилями. Валидатор использует стандартную библиотеку и не вызывает
модели или приложение. Структурная проверка не доказывает смысловую правильность
разметки; её авторский просмотр описан выше.

Локальный отчёт: `artifacts/benchmarks/launcher-basic-v1/review.json`.
Авторский источник с реальными названиями хранится в игнорируемом
`artifacts/benchmarks/author_launcher_basic_v1.py`. Сложные JSON-наборы не изменены.
