# launcher-independent-v1

Независимый набор для проверки выбора одного объекта из полного каталога.
Написан с нуля 6 октября 2026 года, после прежних экспериментов. Это оценочные
данные: в обучение, подбор checkpoint и генерацию обучающих перефраз их не включать.

**200 новых запросов, 40 целевых объектов, новый вымышленный каталог из 177 объектов**:
139 приложений, 20 папок, 18 файлов. Каждому целевому объекту соответствуют пять
авторских команд. Validation содержит 50 запросов к 10 целям, test — 150 к 30
другим целям. Целевые ID и группы перефраз не пересекаются между разбиениями.
Каталог одинаков для обоих разбиений, порядок его объектов перемешан независимо
от порядка разметки.

| Представление | Вход модели | Файлы |
| --- | --- | --- |
| Чистое | Новый авторский текст | `clean/catalog.json`, `clean/validation.jsonl`, `clean/test.jsonl` |
| Голосовое | Настоящий ответ STT на новую шумную TTS-запись | `asr/catalog.json`, `asr/validation.jsonl`, `asr/test.jsonl` |

Это две связанные версии **одних и тех же 200 команд**, а не 400 независимых задач.
Точность считать отдельно по представлению и разбиению. Старый `launcher-asr-v1`
остаётся отдельным стрессовым профилем с прежними фразами и моделью Turbo.

## Что новое

Новые задачи включают осмотры ульев, температурные ступени обжига, ткацкие
переплетения, стратификацию семян, описание снежных слоёв, парусный такелаж и
редактирование сценического света. Папки и файлы принадлежат новым вымышленным
проектам. Для приложений добавлены близкие по теме объекты с другой функцией;
для папок и файлов — другие материалы того же нового проекта. Запросы написаны
как команды пользователя, без намеренной неверной раскладки, отрицаний и ловушек.

| Исходная команда | Правильный объект |
| --- | --- |
| Хочу составить схему, как переплетаются основа и уток | Нитяной раппорт |
| Хочу настроить нагрев и выдержку керамической печи | Гончарный цикл |
| Открой папку со схемами изготовления реквизита для Хрустального карниза | Хрустальный карниз — реквизит |
| Дай файл сценария смены света для Мелового амфитеатра | Меловой амфитеатр — световые переходы.json |

Названия, описания, ID, исходные запросы и целевые группы не перенесены из прежних
наборов. Общие русские слова и обычные формы просьб вроде «открой файл» естественно
повторяются; отсутствие совпадений не означает отсутствие общего языка.

## Проверка пересечений

`overlap_sources.json` фиксирует SHA-256 **47 прежних файлов**: canonical данные
`launcher-v1`, `launcher-basic-v1`, `launcher-asr-v1` на реальных и вымышленных
каталогах, `launcher-transfer-v1`, оба обучающих набора `launcher-train-v1` и
`launcher-stt-train-v1`, а также прежние ASR-пробы. Обнаружение источников идёт по
всем прежним manifest в `data/benchmarks`, `data/training`, `artifacts/benchmarks`
и перечисленным в них файлам; отдельно включены сохранённые ASR-сравнения.
Копии экспортов тех же примеров и прогнозы моделей не являются новыми исходными
примерами и в этот список не входят.

Проверены 25 555 вхождений прежних запросов, включая исходные фразы и расшифровки:
21 248 уникальных текстов после нормализации. Тексты сравниваются после Unicode
NFKC, приведения регистра, замены `ё` на `е`, удаления пунктуации и нормализации
пробелов. Новые clean и ASR тексты проверяются против общего прежнего множества.
Также проверяются ID объектов/примеров/групп, названия и aliases, описания, SHA-256
чистых и шумных WAV и имена TTS-голосов. Результаты находятся в
`overlap_report.json`. Изменение или добавление прежних данных требует нового
сравнения и ревизии; устаревший отчёт не проходит проверку.

## Голосовая часть

Каждый новый текст озвучен через `edge-tts==7.2.8`:
`ru-RU-SvetlanaNeural` для validation, `ru-RU-DmitryNeural` для test. Эти голоса
отличаются от старых Microsoft Irina Desktop / Microsoft Pavel. Из MP3 получен
mono PCM16 WAV, 16 kHz, через `imageio-ffmpeg==0.6.0`. Темп: −4%, 0% или +4%.
Голоса связаны с разбиениями, поэтому такой тест не доказывает обобщение на
произвольных человеческих дикторов.

Применены четыре заранее закреплённых мягких шумовых условия с SNR 30/26/22/18 dB.
Шум воспроизводится по seed; сохранены параметры, длительности и хеши аудио.
Это синтетическая речь с синтетическим шумом: человеческих записей и реальных
микрофонных измерений здесь нет. [Проект edge-tts](https://github.com/rany2/edge-tts)
описывает используемый сервис озвучивания.

Шумные записи отправлены в **Groq `whisper-large-v3`**, `language=ru`, JSON,
без prompt с чистым текстом или каталогом. Использован текущий клиент приложения;
его хеш закреплён до вызовов. Это полный Large V3, а не старый Turbo.
[Параметры Speech-to-Text API](https://console.groq.com/docs/speech-to-text).

`asr/clean_queries.jsonl` связывает запись с исходным запросом и целью;
`recordings.jsonl` хранит акустические параметры; `transcriptions.jsonl` содержит
точный текст, возвращённый клиентом API, статус, время запроса и параметры ASR.
Внешние пробелы убирает клиент приложения. Расшифровки не исправляются, не заменяются
чистыми фразами и не исключаются по результатам decision model. Ответы API
кэшируются по ID записи, хешу аудио и параметрам модели. WAV и исходные MP3 лежат
в игнорируемом `artifacts/benchmarks/launcher-independent-v1/audio`.

Смысл изменённых расшифровок проверен автором относительно каталога и исходного
намерения. `asr_review.jsonl` содержит `preserved`, `lost`, `uncertain` или
`not_reviewed`; авторские оценки привязаны к SHA-256 расшифровки. Независимой
человеческой проверки разметки нет. Статистика находится в ASR manifest.

Итог: **200 непустых ответов**, 161 фраза без отличий после нормализации и 39
изменённых фраз, просмотренных автором. Все 200 отмечены как `preserved`;
это оценка сохранности намерения, а не измеренная точность decision model.
Общая длительность шумных записей — 931,92 секунды, по 50 записей на шумовое
условие. Финальная проверка не нашла пересечений ни по одной из восьми категорий.
Например, «Дай файл, в котором записаны дегустационные оценки Сухарного причала»
стало «DiveFile, в котором записаны дегустационные оценки сухарного причала.»;
описание содержимого файла сохранилось.

## Оценка

Модель получает только `query` и весь `catalog.objects`: ID, название, тип,
описание, aliases. `expected_object_id`, `rationale`, `group_id`, tags, исходный
текст голосовой команды и результаты смыслового просмотра во вход не попадают.
Во всех исходных командах нужно выбрать один объект и действие `open`.

Метрика — доля правильно выбранных ID по **всем** строкам разбиения. Пустой ASR
или потеря различающего слова остаются ошибкой голосового конвейера с исходной
целью в gold. Необходимо отдельно показывать clean accuracy и ASR accuracy;
голосовую неопределённость отмечать по review, без удаления строк из знаменателя.
Уточнения и отказы этот набор не оценивает. Во время оценки приложения не открывать.

Test оставлять для проверки закреплённого решения. После использования test
для изменения модели он перестаёт быть независимым подтверждением следующего
изменения. В ходе сборки этого набора decision models не вызывались.

## Проверка и воспроизведение

Команды запускаются из корня проекта. Обе проверки ниже работают без сети:

```powershell
.\.venv\Scripts\python.exe -I -X utf8 scripts\independent_dataset.py validate
.\.venv\Scripts\python.exe -I -X utf8 scripts\independent_dataset.py validate --text-only
```

Первая дополнительно проверяет хеши всех WAV; вторая подходит для переносимых
текстовых данных без аудио. Источники прежних наборов, перечисленные в
`overlap_sources.json`, необходимы для повторной проверки отсутствия пересечений.
Чистую часть отдельно проверяет существующий `validate_benchmark.py`.

`authoring.json` хранит исходную ручную разметку. `prepare` создаёт frozen clean
и ASR plan, `synthesize` делает аудио, `transcribe` вызывает STT с сохранённым
ключом приложения или `GROQ_API_KEY`, `finalize` фиксирует итоговые файлы и отчёт.
Зависимости TTS установлены отдельно от окружения приложения:

```powershell
uv run --no-project --isolated --cache-dir artifacts\benchmarks\launcher-independent-v1\uv-cache --python .venv\Scripts\python.exe --with edge-tts==7.2.8 --with imageio-ffmpeg==0.6.0 python -I -X utf8 scripts\independent_dataset.py synthesize
```

Обычная проверка не переозвучивает данные и не вызывает API. При повторной
озвучке онлайн-сервис может изменить звук, поэтому сравнение выполняется на
сохранённых записях; прежние ASR-ответы нельзя переиспользовать для другого WAV.
