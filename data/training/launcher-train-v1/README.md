# launcher-train-v1

Обучающий текстовый набор для выбора **одного однозначно заданного объекта**:
`query + full_catalog → open(object_id)`. Подготовлен 4 октября 2026 года.
Все названия, проекты и метаданные вымышлены; личная база не изменялась.

## Объём и происхождение

| Показатель | Значение |
| --- | ---: |
| Обучающие строки | 5 664 |
| Исходные запросы до подстановки названий | 708 |
| Семейства сценариев | 117 |
| Каталоги | 8 |
| Объекты в каждом каталоге | 177: 139 программ, 20 папок, 18 файлов |
| Разные целевые ID | 1 416 |
| Разные нормализованные фразы | 4 474 |
| Цели: программы / папки / файлы | 4 448 / 640 / 576 |
| Строки с небольшой опечаткой в названии | 440 |

Автор задал 177 профилей и по четыре исходных запроса на профиль. Восемь
подстановок меняют названия продуктов, имена проектов, месяцы и ID объектов.
Таким образом, **5 664 строки не являются 5 664 независимыми сценариями**.
Общие конструкции вроде «Запусти {name}» повторяются; 170 запросов по назначению
повторены на разных каталогах, где правильные ID различаются.

Состав: 85 программ с различными назначениями, 27 пар вариантов одной программы,
папки пяти проектов и документы трёх из них. Запросы включают названия,
альтернативные названия, назначение, разрядность, режим, профиль, статус папки,
формат файла, черновик/итоговую версию и конкретный месяц. Есть небольшие опечатки;
пять потенциальных опечаток отброшены, поскольку сближали название с другим
объектом в том же каталоге. Неправильная раскладка, намеренные ловушки, отсутствующие
цели, уточнения и отказы в эту версию не включены.

Примеры из первого каталога:

| Запрос | Единственная цель |
| --- | --- |
| Хочу увидеть, какие папки занимают больше всего места на диске | Программа с описанием карты занятого дискового пространства |
| Открой 64-битную командную оболочку Батолино | Батолино — 64 бита; рядом есть вариант 32 бита |
| Мне нужен каталог с исходными данными проекта Липовая терраса | Липовая терраса — исходные данные; рядом рабочая папка и архив |
| Нужен утверждённый итоговый отчёт проекта Липовая терраса в PDF | Липовая терраса — итоговый отчёт.pdf; рядом черновик DOCX и папка отчётов |

Это авторская синтетика с детерминированными подстановками, без пользовательских
логов, ответов учителя и настоящего ASR. Автор проверил назначения и различия
вариантов; независимой человеческой проверки разметки пока нет. Структурный
валидатор подтверждает целостность и соответствие исходной разметке, а не
семантическую правильность каждой аннотации.

## Файлы и контракт

- [profiles.json](profiles.json) — воспроизводимый источник: метаданные и запросы профилей.
- [catalogs.jsonl](catalogs.jsonl) — восемь снимков с `catalog_id`, хешем и полным списком объектов.
- [train.jsonl](train.jsonl) — запросы, ссылки на каталоги, эталонный ID и происхождение каждой строки.
- [manifest.json](manifest.json) — SHA-256, статистика, протокол и хеши отложенных наборов.

Каждая строка train содержит `id`, `query`, `catalog_id`, `expected_action`,
`expected_object_id`, `input_type`, `group_id`, `seed_id`, `tags`, `source`,
`rationale` и `augmentation`. Последнее поле хранит исходный запрос и замену
для опечаток, иначе равно `null`.

Модель получает только запрос и все объекты указанного каталога. Поля объектов:
`object_id`, `name`, `kind`, `description`, `aliases`. Пути, команды запуска,
пояснения эталона, группы и происхождение не входят во вход модели.

## Отложенная оценка

В обучении нет целевых ID, названий целей и нормализованных запросов из четырёх
существующих наборов: базового/сложного профилей на реальном/вымышленном каталогах.
Их файлы сохранены без изменений; хеши записаны в manifest. Каталоги обучения
созданы отдельно, поэтому отложенные целевые объекты не присутствуют даже среди
обучающих вариантов.

Основная оценка использует существующие validation/test; точность базового и
сложного профиля считать отдельно. Не делить train случайно по строкам: один
исходный запрос имеет несколько подстановок. Для дополнительного разбиения
нужно целиком переносить семейства `group_id`, включая оба варианта программы
и связанные файлы/папки проекта. Общие команды открытия и назначения могут
встречаться в train и оценке: это проверка переноса на другие объекты, а не
обещание новых намерений или новых языковых шаблонов на тесте.

## Проверка, воспроизведение и экспорт

Из корня репозитория:

```powershell
.\.venv\Scripts\python.exe -I -X utf8 scripts\training_dataset.py validate
.\.venv\Scripts\python.exe -I -X utf8 scripts\training_dataset.py build
.\.venv\Scripts\python.exe -I -X utf8 scripts\training_dataset.py export
```

Build воспроизводит train из profiles.json с фиксированным seed 20261004 и
сверяет пересечения с доступными отложенными наборами. Validate также проверяет
сохранённые хеши оценки, уникальность ID, полноту каталогов, правильность
эталонных ссылок и восстановление всех строк из исходных профилей. В переносимой
копии без личных artifacts проверяются два вымышленных набора; отсутствие
приватных отмечается в отчёте явно.

Экспорт создаёт `artifacts/training/launcher-train-v1/kev.train.jsonl` и отдельный
manifest. Формат соответствует [документации Kev](https://github.com/jaredpalmer/kev#by-hand):

```json
{
  "state": {"query": "Открой 64-битную командную оболочку Батолино"},
  "questions": {
    "open": {
      "type": "choice",
      "instructions": "Выбери один объект каталога, который нужно открыть.",
      "criteria": {
        "obj_...": "[app] Батолино — 64 бита. Командная оболочка языка Рона..."
      },
      "label": "obj_..."
    }
  }
}
```

Пример сокращён; каждая настоящая строка содержит **все 177 вариантов**, включая
похожих соседей. Ключ label — настоящий непрозрачный ID цели. Порядок вариантов
меняется отдельно для каждого запроса, воспроизводимо по ID строки. Все позиции
от 0 до 176 встречаются среди эталонов; в текущем экспорте на позицию приходится
от 17 до 50 ответов. Экспорт занимает около 247 MiB и остаётся в игнорируемых
artifacts; исходные данные занимают около 4 MiB. Никаких программ экспорт не открывает.

## Бюджет токенов для Kev

Проверены **все 5 664 строки**, без обрезания, токенизатором
`Qwen/Qwen3.5-4B-Base@1001bb4d826a52d1f399e183466143f4da7b741b` с порядком сериализации
Kev `fe64b1274ea7f80d4095866df90666abb03e9cf6`:

| Измерение | Результат |
| --- | ---: |
| Токены state с запросом | 7–30 |
| Полная строка: запрос, инструкция и 177 вариантов | 10 889–11 169 |
| Строки, помещающиеся в стандартный контекст обучения Kev | 0 / 5 664 |
| Строки, помещающиеся с `--max_state 16384` | 5 664 / 5 664 |

При обучении этим экспортом нужен **`--max_state 16384`**: этот параметр в
[коде Kev](https://github.com/jaredpalmer/kev/blob/fe64b1274ea7f80d4095866df90666abb03e9cf6/kev/model.py)
увеличивает и бюджет ветки с вариантами. Стандартный запуск отбрасывает слишком
длинные записи, поэтому нельзя принимать нулевую или сокращённую обучающую
выборку за успешное использование датасета. Отчёт с хешами и замером:
`artifacts/training/launcher-train-v1/kev.train.tokenization.json`.

Замер выполнен только токенизатором и проверкой формата сериализации; веса модели
не загружались, обучение и расход GPU-памяти не проверялись. При смене токенизатора,
формата вариантов или каталога бюджет нужно пересчитать. Для иной decision-модели
используйте общий train и собственный адаптер; наличие Kev-экспорта не означает
совместимость его JSONL с любым другим тренером.
