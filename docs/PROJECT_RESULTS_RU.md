# Jev Launcher: что получилось после обучения моделей

Jev Launcher — учебный лаунчер для Windows. Пользователь пишет или произносит команду, а приложение ищет программу, файл или папку в локальном каталоге. Мы проверяли, насколько локальные модели справляются с русскими запросами и ошибками распознавания речи.

В приложении оставлены **Laya**, **дообученная E5** и **RuModernBERT**. Laya остаётся основной, поскольку проект посвящён decision-моделям. E5 — быстрый вариант для обычного использования, RuModernBERT — отдельный reranker для сравнения подходов.

## Что проверяли

Для обучения подготовили 22 656 строк: чистые запросы и искажённые варианты одних и тех же фраз. Связанные примеры разделяли по группам. Обучение запускали на Kaggle, выбранные веса проверяли локально на CPU.

Сравнили смесь данных с самого начала и чистый старт. В следующих запусках сохраняли промежуточные веса и выбирали их по ошибке на валидации, чтобы следить за переобучением. Новый вымышленный каталог с новыми командами использовали для проверки переноса, без выбора обучаемых весов по его результатам.

Самая трудная проверка — старый шумный STT: синтезированную речь зашумляли и распознавали Whisper. Часть расшифровок теряла смысл запроса. Новый набор с полным Whisper Large-V3 заметно чище, поэтому его результаты показываем отдельно. Живую речь людей здесь не измеряли.

## Почему оставлены именно эти три модели

| Модель | Старый сложный STT | Новый ASR test | Измеренная задержка после загрузки |
| --- | ---: | ---: | ---: |
| **Laya FP32** | **80%** | 141/150 — 94% | Около 0,78 с |
| **Дообученная E5** | **82%** | 143/150 — 95,3% | Около 14–15 мс |
| **RuModernBERT** | **71%** | 143/150 — 95,3% | Около 0,12–0,15 с |

Старый STT — среднее двух каталогов, по 50 команд в каждом; его синтетическая часть участвовала в выборе весов. Задержки получены в разных проверках на i7-13700H: это ориентиры с сохранёнными протоколами, а не один общий замер. Для Laya указан полный прогон пути приложения; для E5 и RuModernBERT — повторные прогоны. Таймер включает поиск и выбор объекта, но исключает распознавание голоса, загрузку модели и построение первого индекса. Постоянную задержку меньше полсекунды для Laya мы не подтвердили.

**Laya — основной учебный вариант.** Исходная E5 отбирает до 20 кандидатов, Laya читает запрос и карточки и выбирает объект. Она хорошо показала себя на новых приложениях и лучше RuModernBERT справилась со старым сложным STT. Основной она стала ради изучения decision-модели; лидером скорости или точности её не объявляем.

**Дообученная E5 — вариант с минимальной задержкой.** Она сравнивает вектор запроса с заранее вычисленными векторами карточек, без следующей модели выбора. Дообучение подняло среднее десяти сценариев с 80,5% до 89,4%, сложный STT — с 65% до 82%. По нашим измерениям это удачный практический компромисс качества и скорости.

**RuModernBERT — быстрый reranker.** После исходной E5 он отдельно оценивает каждую пару «запрос — карточка». Он быстрее Laya и хорош на новом ASR, но слабее обеих моделей на старом шумном STT. Оснований считать его лучше обученной E5 в среднем нет. Он оставлен для сравнения архитектур, без обещания практического выигрыша над E5.

## Что дали остальные эксперименты

Kev оказался самым точным на сложном STT — 87%, но около 4,5 секунды на запрос слишком много для быстрого запуска. Nano после чистого старта получил 72% против 68% у смеси с начала обучения. Продолжение с меньшей скоростью обучения не улучшило критерий выбора весов; это результат конкретного рецепта, а не доказанный предел модели.

Квантование Laya ускорило часть запросов, но снизило сложный STT с 80% до 64% и не обеспечило устойчивые полсекунды. RuBERT-tiny2 с новой головой выбора оказался быстрым — около 66 мс, — но получил только 25% сложного STT. Эти варианты убраны из обычного списка моделей; результаты и веса сохранены.

Обученная E5 перед фиксированной Laya не дала общего улучшения: среднее десяти сценариев изменилось с 88,15% до 87,95%, сложный STT — с 80% до 78%. Правильный объект чаще попадал в двадцатку, но Laya чаще ошибалась при выборе. Поэтому обученная E5 работает самостоятельно, перед Laya остаётся исходная.

## Температура и качество каталога

Температуру Laya подобрали отдельно от обучения весов. Значение **T = 2,49** выбрано по loss на 100 примерах validation. На 300 примерах test из других групп loss снизился с 0,404 до 0,241, а ошибка калибровки ECE — с 4,59% до 3,11%. Число правильных ответов осталось 283/300: температура меняет уверенность, сохраняя порядок вариантов.

У английской Laya есть настройка около 0,1 для большого числа вариантов. На наших весах она почти всегда давала уверенность 100%, включая ошибки. T = 2,49 тоже не улучшила все показатели: на старом STT loss вырос, хотя ECE снизилась; на test немного ухудшилась другая метрика вероятностей — Brier. Калибровка действует для наших весов и двадцати кандидатов. Высокая уверенность не используется как разрешение автоматически открыть объект.

Без описаний качество E5 сильно падает. В приложение добавлено заполнение пустых карточек из метаданных Windows и подтверждённых пакетов WinGet. На проверенном каталоге появились 12 описаний: теперь они есть у 78 из 139 приложений. Покрытие неполное, а новые описания иногда помогают, иногда ухудшают выбор. Результат на подробных искусственных карточках нельзя обещать для любого компьютера.

Числа получены на уже известных наборах, преимущественно с синтезированной речью и одним запуском каждого рецепта обучения. Они помогают выбрать модели для этого проекта, но не доказывают универсальное превосходство.
