# RuBERT-tiny2 с головой выбора

Historical experiment record. Paths under `artifacts/` refer to local files; published predictions and ledgers are in [public evidence](../results/README.md).

## Статус и цель

Эксперимент начат 7 октября 2026 года по предложению пользователя проверить компактный RuBERT с decision-головой. До этого **ruBERT-tiny2 + новая голова выбора** был резервным кандидатом в TRAINING_POOL экспериментального worktree; готового обученного результата в проекте не было. Схема выбора по оценкам пар уже применялась у Nano и RuModernBERT.

Эксперимент завершён и проверен 8 октября. Приватный [Kaggle notebook v1](https://www.kaggle.com/code/matveyvarfolomeev/launcher-rubert-tiny2-choice-v1) получил статус COMPLETE; все 22 выходных файла скачаны. После 568 обновлений выбраны веса шага 142. Полный CPU800 и повторный E5→ID CPU400×2 прошли аудит. **Модель быстрая, но этот рецепт не дал сравнимого качества: 25% на старом шумном STT и 26,25% среднего десяти сценариев.** Laya FP32 шага 568 остаётся основной моделью приложения.

## Архитектура и исходные веса

[cointegrated/rubert-tiny2](https://huggingface.co/cointegrated/rubert-tiny2/tree/e8ed3b0c8bbf4fb6984c3de043bf7d2f4e5969ae) закреплён на revision e8ed3b0c8bbf4fb6984c3de043bf7d2f4e5969ae. Это русский BERT encoder с тремя слоями, hidden size 312 и двумя типами сегментов. Исходная карточка и контрольные суммы всех скачанных файлов сохранены.

Новая скалярная голова создаётся один раз с seed 20261007. Все encoder-параметры точно совпали с исходным safetensors; старые pretraining heads исключены. Модель с головой выбора содержит **29 194 081 параметр**. Исходные 29,4 млн в карточке модели включают другую голову; это разные подсчёты.

Начальные веса выбора: SHA-256 788319ace54cafd0633fd585d00e82c60e407f6cfca97b16b4a269bfb7c5e78f. Сохранение и повторная загрузка воспроизвели logits точно. Никакие train или validation метки для инициализации не использовались.

~~~mermaid
flowchart LR
    Q["Запрос"] --> E["E5: 20 карточек"]
    E --> P["20 пар: запрос + одна карточка"]
    P --> B["RuBERT: совместные признаки пары"]
    B --> H["Один score для каждой пары"]
    H --> S["Softmax по 20 scores"]
    S --> I["Программа: позиция → object_id"]
~~~

BERT получает token_type_ids 0 для запроса и 1 для карточки. Проверено, что оба сегмента сохраняются при токенизации и подготовке batch. Предел пары — 2048 токенов; превышение прерывает запуск вместо скрытой обрезки. Обучаются encoder и новая голова, loss — cross-entropy по 20 вариантам. ID используется только для вычисления индекса правильной карточки.

Encoder уже знает язык, но случайная голова пока не знает, какие признаки нужны для выбора. Пользователь верно предположил качество около случайного угадывания. При 20 вариантах ориентир — около 5%, а измеренный baseline на 150 строках дал 4 правильных ответа, 2,67%, и NLL 3,0021, близкий к ln(20) ≈ 2,9957. Один фиксированный seed на небольшой выборке не обязан дать ровно 5%. Фиксированная инициализация обеспечивает повторяемые ответы, а не новую случайную карточку при каждом запуске. Вероятности после softmax сравнивают предъявленные кандидаты и не являются проверенной оценкой надёжности всей цепочки.

Размер файла и число параметров недостаточны для вывода о скорости. Большая часть RuBERT занимает словарь; вычислительных блоков три против двенадцати у проверенного RuModernBERT. Фактическая задержка измерена на одинаковом CPU-пути ниже.

## Протокол одного запуска

| Параметр | Значение |
| --- | --- |
| Train | Прежние 22 656 строк: 5 664 clean + 16 992 STT |
| Выбор весов | Прежняя synthetic validation: 150 строк, условный NLL по группам и профилям |
| Кандидаты | Закреплённые E5 top-20; вставки целей только на train, ноль на validation |
| Порядок | Первые 2 272 строки clean, затем смесь оставшихся; seed 20261005 |
| Максимум | Один проход, 1 416 обновлений |
| Обновления | Все веса encoder и головы; FP32; effective batch 16, micro 2 |
| AdamW | lr 2e-5, weight decay 0,01, warmup 6%, gradient clip 1 |
| Проверка / stopping | Каждые 142 обновления; patience 3, min_delta 0,005 |
| Исходное состояние | Участвует в выборе лучших весов |
| Отложенная оценка | Известные 800 представлений, 10 сценариев с равными весами |
| Скорость | Два полных CPU-прохода по 400 входам: E5 → 20 пар → ID |

Промах retrieval сохраняется ошибкой accuracy всей цепочки. Условный NLL для stopping использует строки с достижимой целью. Старый test не открывается; личные каталоги и известные transfer/test данные на Kaggle не отправляются. Уже изученные 800 представлений не становятся новой слепой проверкой.

## Проверки перед отправкой

13 существующих и новых тестов прошли, включая сохранение BERT-сегментов и исключение меток из входа. Ruff и компиляция всех code cells прошли. Ноутбук создан из шаблона experiment через jupyter-notebook.

CPU-проверка на 32 train-строках выполнила два конечных обновления; последние веса изменились, stopping сохранил исходные. Это проверка работоспособности обучения, без оценки итогового качества. Общий тренер и аудит переиспользованы; прежний GPU/CPU800 аудит ModernBERT повторно прошёл без изменений его данных или результатов.

Приватный dataset launcher-rubert-tiny2-choice-training-v1 получил статус ready. Notebook проверяет точный SHA manifest, каждого входного файла и исходных весов перед обучением.

## Как проходило обучение

Kaggle использовал Tesla T4, Torch 2.11.0+cu128 и Transformers 5.12.1. Тренер отработал за **150,43 с**; установка пакетов и ожидание GPU в это число не входят. Выполнены 568 конечных обновлений, остановка — validation_patience. Исходное состояние и четыре промежуточные проверки сохранены.

| Шаг | Validation NLL | Basic /50 | Difficult /50 | STT /50 | Решение |
| ---: | ---: | ---: | ---: | ---: | --- |
| 0 | 3,00207 | 1 | 0 | 3 | Исходная случайная голова |
| **142** | **2,58128** | **13** | **9** | **14** | **Выбранные веса** |
| 284 | 2,62173 | 12 | 10 | 8 | Первая проверка без улучшения |
| 426 | 2,61434 | 10 | 8 | 7 | Вторая проверка без улучшения |
| 568 | 2,61915 | 12 | 9 | 9 | Третья; остановка |

Выбранный шаг получил **2 272 clean-строки и ни одной STT train-строки**: он совпал с концом чистого старта. Последние веса получили 9 088 строк, включая последующую смесь. Это не полное прохождение всех 22 656 строк. Лучшие веса выбирались по прежней synthetic validation NLL; известные real, transfer и independent данные не использовались для stopping.

![Фактическое обучение RuBERT-tiny2](../assets/experiments/rubert-learning-curves.png)

Синяя линия — train CE, усреднённый по 50 шагам; отдельные batch показаны светлым цветом. Оранжевые точки — одна и та же validation. Train продолжает улучшаться, а validation после 142 уже хуже. Правый график показывает, что accuracy также не растёт последовательно. Мы возвращаемся к выбранным весам, а не выдаём последние за лучшие. Разница уровней train/validation сама по себе не измеряет переобучение: различаются строки, веса групп и режим dropout.

Обучение повысило accuracy synthetic validation с 4/150 до 36/150, однако задача осталась освоена слабо. Градиенты и веса конечны. Сохранены все BERT-сегменты; input manifest, порядок строк, выбранный шаг и hashes прошли аудит. Максимальная длина train-пары — 71 токен, validation — 53; обрезок нет. На 150 validation-строках top-1 CPU и GPU совпал полностью, максимальная разница вероятностей 8,94×10⁻⁸.

Среднее десяти сценариев с равными весами — **26,25%**. Обычная доля по всем строкам — **306/800 = 38,25%**. Эти числа различаются из-за размера independent clean/ASR: по 200 строк вместо 50. Два старых шумных STT-каталога дают равновесное среднее **25%**. Роли validation и test сохранены: independent clean — val 32/50 и test 76/150; independent ASR — val 35/50 и test 90/150. Это уже изученный набор, поэтому новый запуск не получает независимого подтверждения на слепом test.

Промахи E5 не объясняют основную потерю: на real STT цель доступна в 44/50 shortlists, но модель выбирает лишь 11/44 доступных; на synthetic STT — 14/47. В третьем каталоге цель доступна во всех 100 строках, правильных ответов всего три.

| Выбранная модель | Старый шумный STT: среднее real/synthetic | Среднее 10 сценариев | Новый ASR test /150 |
| --- | ---: | ---: | ---: |
| Laya FP32, 568 | 80% | 87,85% | 141 |
| RuModernBERT, 426 | 71% | 84,90% | 143 |
| Nano clean-first | 72% | 79,05% | 125 |
| RuBERT-tiny2 + новая голова, 142 | 25% | 26,25% | 90 |

Предыдущие модели здесь взяты из закреплённой [сводки](FINAL_MODEL_COMPARISON_RU.md); их веса и результаты не менялись. RuModernBERT начинал с обученного русского reranker, а RuBERT — с языкового encoder и случайной головы. Это разные стартовые состояния, и сравнение одного общего рецепта не отделяет влияние архитектуры от способа адаптации.

## Скорость: два полных прохода

i7-13700H, FP32, 6 потоков на шести быстрых физических ядрах, spinning E5 отключён. Заранее загружены веса и индекс; перед таймером два прогрева. Для каждого запроса заново выполнены E5 retrieval, подготовка 20 пар, RuBERT и сопоставление с ID. Второй проход идёт в обратном порядке. ASR, загрузка, первоначальное индексирование и запись артефактов исключены.

| Проход | Входов | Медиана | p95 | Максимум | Более 500 мс |
| --- | ---: | ---: | ---: | ---: | ---: |
| Первый | 400 | 66,30 мс | 99,05 мс | 133,41 мс | 0/400 |
| Второй | 400 | 66,53 мс | 102,81 мс | 157,96 мс | 0/400 |

В первом проходе медиана E5 — 15,48 мс, подготовки входа — 4,22 мс, выбора и mapping — 45,80 мс; во втором — 16,30 / 4,35 / 44,79 мс. Медианы частей не обязаны складываться в медиану полного пути. Постпроверка пересчитала каждую стадию, сумму таймеров и все квантили по 800 строкам. Каждый ID воспроизвёл контрольное качество; максимальная разница вероятностей 7,45×10⁻⁸. Все замеры меньше 500 мс в этих условиях, без обещания той же задержки при любой нагрузке.

## Вывод и границы

Компактный encoder оказался самым быстрым из этих полных neural-замеров, но **сравнимого дообученного score не получил**. Laya остаётся основной, RuModernBERT — проверенной быстрой альтернативой; этот RuBERT checkpoint не добавлен в приложение как качественный вариант.

Наблюдается улучшение относительно случайной головы и ухудшение validation после раннего минимума. Абсолютный предел RuBERT этим не установлен. Использовали одинаковый lr 2e-5 для обученного encoder и новой головы. Отдельный прогрев головы или больший lr только для неё — разумные следующие гипотезы, но причина слабого качества не доказана и дополнительные запуски не выполнялись. Больше эпох при этом рецепте не гарантирует улучшения.
