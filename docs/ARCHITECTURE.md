# Архитектура

Каталог, поиск и открытие не зависят от Qt. Интерфейс — клиент этих модулей, а экспериментам доступны те же данные и постоянные ID.

~~~mermaid
flowchart LR
    UI["QML: поиск, каталог, настройки"] --> C["Controller: Qt-адаптер"]
    C --> J["Jobs: фоновые задачи"]
    J --> D["Discovery: источники Windows"]
    D --> DB["Catalog: SQLite"]
    C --> DB
    C --> F["Search: текстовый фильтр"]
    C --> L["Launch: открыть по ID"]
    L --> DB
    C --> A["Recorder: аудио в памяти"]
    A --> S["Speech: Groq ASR"]
    S --> C
    CLI["CLI / Python-эксперимент"] --> DB
    DB --> SNAP["Полный каталог для модели"]
~~~

## Каталог

Catalog открывает короткоживущие соединения SQLite: объект можно использовать из фоновой задачи без передачи соединения между потоками. Обновление источников выполняется одной транзакцией.

В objects хранятся ID, идентичность запуска и JSON записи. sources связывает источники с объектами. settings содержит параметры приложения. Версия схемы — 1; неизвестная версия отклоняется вместо изменения чужой базы.

merge_scan снимает доступность только у записей успешно прочитанного источника. Сбой источника оставляет прежние записи. Пользовательские изменения помечаются как overrides: новые метаданные не затирают описания, названия и альтернативные названия, включая намеренно пустое описание.

Дедупликация использует зарегистрированный AppID либо цель, аргументы и рабочую папку. Название само по себе не является ключом. Существующий ярлык сохраняется как способ открытия, когда другой источник описывает ту же цель.

## Граница открытия

Вход из интерфейса — launch_by_id(catalog, object_id). Он получает объект из базы, проверяет доступность и вызывает Windows Shell либо subprocess со списком аргументов и shell=False.

Текст запроса и ответ будущей модели не становятся командами. Успешный вызов означает отправку команды, а не готовность окна. Реальные окна проверяются отдельным Windows-интеграционным сценарием.

## Фоновые задачи

Jobs содержит ограниченный QThreadPool и доставляет результат в GUI через сигналы Qt. В фоне работают сканирование, открытие, загрузка иконок, преобразование аудио и сетевое распознавание.

QML-провайдер иконок читает только готовый кеш. Windows-иконки извлекаются заранее в фоне; QML не дожидается Python-провайдера при уничтожении окна.

Recorder использует формат микрофона. После остановки исходный PCM превращается в 16-битный моно WAV в рабочей задаче. Аудио не пишется на диск. Для поздних ASR-ответов проверяется номер запроса; отмена или ручное изменение ввода делает старый результат неприменимым. Отмена результата не гарантирует отмену уже отправленного запроса на стороне сервиса.

При выходе приложение останавливает запись, отменяет дальнейшую загрузку иконок и дожидается ограниченных фоновых задач. Уже отправленный HTTP-запрос может задержать завершение до своего таймаута.

## Окно и один экземпляр

Qt.Tool делает окно плавающим служебным окном; горячая клавиша и трей возвращают его. Настройки менеджера окон не изменяются.

QLockFile защищает каталог данных от второго экземпляра GUI. Повторный запуск через QLocalSocket просит существующее окно показаться. Сообщение не содержит команд. Разные каталоги данных позволяют держать отдельный экспериментальный экземпляр; для него можно отключить горячую клавишу.

## Где подключать модель

Используйте Catalog.model_catalog() для полного набора включённых и доступных вариантов. Controller.results предназначен для экранного фильтра и не служит входом модели.

Сначала вызывайте модель из отдельного эксперимента и оценивайте выбранный ID. После проверки результатов добавляйте её вызов в Qt-контроллер. Discovery, SQLite и launch.py менять не требуется.

## Упаковка

JevLauncher.spec собирает QML и ресурсы вместе с Python/Qt. Qt в Windows использует системную ICU. Рецепт исключает чужие ICU DLL из PATH: например, Poppler может поставлять библиотеку с тем же именем и несовместимыми экспортами.
