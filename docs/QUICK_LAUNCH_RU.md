# Два окна и компактный запуск

Большое окно открывается при обычном запуске, повторном запуске и активации значка в трее. Оно содержит поиск, каталог, редактор объектов и настройки. Закрытие оставляет приложение в трее; «Выйти» останавливает Qt-приложение и принадлежащий ему процесс модели.

Компактное окно вызывается сочетаниями **Ctrl+Shift+Space** для текста и **Ctrl+Alt+Space** для записи голоса. Оба изменяются в настройках. Прежняя настройка `hotkey` сохранена для текста; `voice_hotkey` добавлена отдельно. Windows ID — `0x4A45` и `0x4A46`. Регистрация двух сочетаний выполняется вместе с восстановлением прежних рабочих сочетаний при конфликте; обмен сочетаний местами поддерживается.

## Поведение

В текстовом режиме поиск запускается после существующей паузы 250 мс. Панель показывает одну карточку top-1: иконку, название и тип. Enter открывает текущий top-1; если ответ ещё не получен, ждёт результат именно на отправленный текст. Отправленный запрос фиксируется до завершения или отмены.

Голосовая горячая клавиша сразу начинает запись. Enter останавливает её и выполняет распознавание → поиск → открытие без второго подтверждения. Кнопка микрофона доступна в текстовой панели. Кнопка «Стоп» сначала возвращает текст и результат; Enter после проверки открывает объект. Enter во время такого распознавания также запоминает намерение открыть.

Пустой запрос ничего не открывает. Повторный Enter во время выполнения не создаёт повторного открытия. Esc, отмена и повторное нажатие текущей горячей клавиши отменяют сессию. Изменение текста до отправки, смена модели и новая сессия не принимают поздние результаты старого запроса. Изменение каталога во время отправленной команды просит отправить запрос заново.

Потеря фокуса до отправки закрывает панель и отменяет запись. После Enter обработка продолжается; отмена остаётся на индикаторе. Ошибка разворачивает панель и сохраняет доступный текст. Отмена предотвращает ещё не отправленную команду Windows; уже отправленную команду она не отзывает.

## Окна и модель

Панель — независимое верхнеуровневое окно `Jev Launcher Quick`, без transient-parent большого окна. Флаги Tool, Frameless и Always-on-top убирают системный заголовок и отдельную кнопку на панели задач. Поверхность около 640 логических пикселей, индикатор — 180×44; прозрачные поля под тень добавляют по 20 пикселей с каждой стороны. Размер ограничен доступной областью монитора с курсором. Центр сохраняется при сжатии и возврате после ошибки.

Используются графитовая и светлая темы, голубой акцент, граница и мягкая тень. Появление занимает 160 мс, изменение размеров — 180 мс. Операции начинаются сразу; анимации не служат таймером запуска. Настройка Windows «Анимация элементов управления и элементов внутри окон» учитывается.

`QuickSession` хранит режим, этап, текст, идентификаторы сессии/запроса и намерение открытия отдельно от поиска большого окна. Оба окна используют один каталог, пул фоновых задач, сервис распознавания и границу запуска по `object_id`. Модель получает только безопасные метаданные каталога, без путей и команд.

Выбранная модель заранее загружается в фоне. Worker сначала отвечает `loaded` после загрузки весов; `ready` появляется после подготовки индекса и прогрева настоящего пути inference. Поиск и подготовка сериализуются в одном процессе. Поколение runtime не позволяет запланированной старой задаче заново загрузить прежнюю модель после переключения. Состояние готовности видно в большом окне. EXE содержит текущий worker и его загрузчики; веса, E5/model-worktree и CPU-среды остаются локальными зависимостями.

## GlazeWM

На текущем GlazeWM панель имеет правильный размер, остаётся поверх окон и отсутствует в списке управляемых окон. Исключение не потребовалось; пользовательская конфигурация не менялась. Если другая версия менеджера всё же размещает панель в сетке, добавьте только это правило в `window_rules`:

```yaml
- commands: ['ignore']
  match:
    - window_process: { regex: '^(JevLauncher|python|pythonw)$' }
      window_title: { equals: 'Jev Launcher Quick' }
```

Большое окно этим правилом не затрагивается.

Автоматические сценарии покрывают текст и голос с подставным ASR/открытием, Enter во время поиска и распознавания, повторный Enter, отмену записи/ASR/поиска/запланированного открытия, новую сессию, смену модели/каталога, пустой запрос и каталог, отсутствие ключа/микрофона, ошибки ASR/модели/открытия. Проверены клавиатурный ввод QML, сжатие с сохранением центра, обе темы, отдельное окно и конфликт/восстановление двух сочетаний.

Полный набор: **211 passed, 1 skipped**; пропуск относится к проверке CPU-весов Laya в отдельной ML-среде. Ruff и `git diff --check` прошли. Оба окна и обе темы просмотрены на Windows при масштабе 125% и дополнительном масштабе Qt до эффективных 200%; проверены поиск, каталог, настройки, редактор, текст/голос, капсула и ошибка.

Сквозной прогон настоящего приложения на копии пользовательского каталога из 177 объектов подтвердил регистрацию стандартных сочетаний и их раздельную обработку через нативный `WM_HOTKEY`, работу трея и повторного запуска. Настоящая Laya выбрала Notepad в текстовом и подставном голосовом сценариях; открытие было подставлено и вызывалось ровно один раз на сессию. PID модели между вызовами не менялся; после «Выйти» процесс завершился. В последнем прогоне большое окно появилось примерно за 2,2 с, готовность модели и полного индекса — за 15,6 с. Это проверка интеграции, а не новая оценка качества или скорости модели.

Упакованный EXE отдельно проверен в изолированном профиле: большое окно, сбор каталога, запуск из кеша, повторный запуск, загрузка bundled worker, подготовка индекса из 166 автоматически обнаруженных объектов и остановка процесса модели при выходе. Последняя сборка показала окно примерно за 1,2 с, каталог за 4,5 с, модель и индекс за 14,3 с; запуск из кеша — около 1,0 с. Отчёты: `artifacts/quick-launch-v1/verified-lifecycle/report.json` и `artifacts/quick-launch-v1/verified-exe/report.json`.

Эмуляция физических сочетаний через SendInput в текущей среде не вызывает `WM_HOTKEY` даже в отдельном минимальном Win32-примере без Qt. Причина не установлена. Регистрация, конфликты и обработка нативных сообщений проверены; физическое нажатие сочетаний остаётся отдельной ручной проверкой. Настоящий микрофон и живой ASR API в новой компактной цепочке не вызывались: запись и ASR для сквозной проверки подставлены.
