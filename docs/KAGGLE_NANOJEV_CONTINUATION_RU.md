# Nano-Jev: один дополнительный проход

Пользователь разрешил проверить продолжение обучения Nano с меньшим learning rate и регулярной валидацией. Ноутбук [launcher-nanojev-continuation-v1](https://www.kaggle.com/code/matveyvarfolomeev/launcher-nanojev-continuation-v1), версия 1, завершён 7 октября 2026 года: Kaggle COMPLETE. Выполнено 426 дополнительных обновлений за 19 минут 20 секунд, после трёх проверок без улучшения выбраны стартовые веса. Их среднее десяти сценариев осталось 79,05%.

## Что проверяем

Первое обучение Nano clean-first прошло один раз по 22 656 строкам и сохранило последние веса. Между началом и концом не было проверок validation. Это не доказывает, что достигнут предел модели.

Теперь начинаем из этих дообученных весов, а не из исходной английской модели. Стартовый файл имеет SHA256 `0df8d201084de2051c1beb6b7e7ec6d6891b3fd8f86318f4ef482d7286404095`. Сам файл и прежние результаты не изменяются. Состояние старого AdamW не сохранялось, поэтому создаётся новый оптимизатор; это продолжение из весов, а не точное возобновление прерванного процесса.

## Зафиксированный протокол

| Параметр | Значение |
| --- | --- |
| Данные | Те же 5 664 clean + 16 992 simulated-STT строки |
| Подача | Перемешанная смесь с начала, seed 20261007 |
| Learning rate | 1×10⁻⁵; раньше 3×10⁻⁵ |
| Оптимизатор | Новый AdamW, weight decay 0,01 |
| Batch | 16 запросов; GPU microbatch 4 |
| Численная точность | FP32: веса, forward, optimizer и validation |
| Бюджет | Максимум один дополнительный проход / 1 416 обновлений |
| Проверка | Каждые 142 обновления и в конце прохода |
| Выбор весов | NLL: равный вес профилей и групп, только достижимые цели |
| Остановка | Три проверки без улучшения больше 0,005 |
| Начальные веса | Участвуют в выборе; при best_step=0 сохраняются побайтово |

Короткий чистый старт повторно не проводим: он уже был в первом проходе. Новых обучающих запросов нет. E5, описания, двадцать кандидатов и их порядок внутри каждого примера прежние. Пять clean и 46 STT положительных кандидатов были добавлены только при первоначальной подготовке train; на validation таких исправлений нет.

Исходные 150 синтетических validation строк отделены по группам от train. Остальные каталоги и личные данные в приватный пакет не входят, не участвуют в stopping и выборе checkpoint. После фиксации весов сравниваем прежние 800 известных представлений: каждый из десяти сценариев имеет одинаковый вес. Это повторная проверка качества, не новый слепой тест.

## Стартовая точка и проверка запуска

Зафиксированные прежние предсказания: среднее десяти сценариев 79,05%, 642/800 правильных ответов, обычная синтетическая validation NLL 0,568330. Сохранённая ссылка на них: `artifacts/kaggle/nano-continuation-evaluation-v1/baseline/`. Она объединяет ранее проверенные CPU300, CPU100 и GPU400; это не новый полный CPU-прогон.

На этих 800 представлениях 18 ошибок связаны с отсутствием цели в E5 top-20, ещё 140 — с неправильным выбором среди кандидатов. Продолжение Nano может исправлять вторую группу; первой нужны изменения retrieval.

Короткий CPU-запуск выполнил два конечных обновления по 32 строкам за 91,25 секунды. Validation loss не улучшился достаточно: выбран шаг 0, checkpoint побайтово равен стартовому, а последние веса изменились. Три стартовых CPU-ответа совпали с прежними; максимальная разница вероятностей 1,34×10⁻⁷. Это проверка загрузки, backward, сохранения и защиты исходного checkpoint, а не измерение итогового качества.

Десять существующих тестов состава данных, разделения групп, группового NLL и stopping прошли. Код нового ноутбука компилируется, старых cell outputs нет. Общие аудит и CPU-таймер расширены для Nano; прежний полный ModernBERT-аудит после изменения снова прошёл. Исходные модельные среды сохранены.

Приватный dataset [launcher-nanojev-continuation-training-v1](https://www.kaggle.com/datasets/matveyvarfolomeev/launcher-nanojev-continuation-training-v1) содержит только разрешённый пакет. Его 14 развёрнутых файлов подтверждены; скачанный manifest побайтово равен локальному, SHA256 `0cea12c910fa27789e3f7fe2729aee9f76e9000faa52c65069bc467efffa0759`.

Фактическая GPU-среда: Tesla T4, Torch 2.11.0+cu128, Transformers 5.6.2. Все 453 120 обучающих и 3 000 validation пар укладываются в 512 токенов, максимум 254/238; усечения нет. Стартовая GPU-валидация точно воспроизвела прежние 42/50 basic, 36/50 difficult, 38/50 ASR и NLL 0,568330. На первом обновлении train CE 0,090019 и норма градиента до clipping 15,3672 конечны. Это подтверждает начало вычислений, а не итоговый прирост.

## Файлы

- `artifacts/kaggle/nano-continuation-preflight.json`: выполненная проверка CPU-запуска.

| **0: выбран** | **0,568330** | 42 | 36 | 38 | 116 |

Все три NLL выше стартового, поэтому правило выбора сохранило дополнительный шаг 0. Последние веса имеют на два правильных ответа больше, однако по заранее выбранному критерию не выигрывают. Остальные каталоги не выбирали checkpoint. Это не доказательство абсолютного предела модели: проверена одна схема продолжения, а не все данные, seeds и learning rates.

Фактический таймер скрипта 1 159,9668 секунды включает загрузку, токенизацию и validation, но не очередь/подготовку Kaggle. Повторно предъявлено 6 816 обучающих строк из 22 656; лимит полного дополнительного прохода не достигнут из-за stopping. В результате выбранных весов эти дополнительные обновления не сохраняются. Скачаны все 26 выходных файлов, включая selected и last; проверены источник, порядок и состав примеров, LR, каждый validation score/ID/NLL, patience, FP32 и SHA256.

Выбранный SHA256 совпадает со стартовым `0df8d201084de2051c1beb6b7e7ec6d6891b3fd8f86318f4ef482d7286404095`; последний — `b46f764013713adb11fd72542867403ec2f0be33ac76cc7cd9bd8e8f87914d63`. Для выбранной модели повторный CPU800 даёт те же 642/800 правильных ID и 79,05% среднего десяти сценариев. Все 800 ответов совпадают с прежней составной оценкой; максимальная разница вероятностей 5,43×10⁻⁶. С выбранными GPU150 все ID также совпадают, максимум 2,98×10⁻⁶. При побайтовом равенстве selected стартовым весам этот полный CPU-результат используется повторно.

## Полный CPU-замер выбранной Nano

| Повтор, 400 запросов | Медиана | p95 | Максимум | Выше 500 мс |
| --- | ---: | ---: | ---: | ---: |
| 1 | 387,35 мс | 442,93 мс | 883,78 мс | 4/400 |
| 2 | 408,34 мс | 471,70 мс | 881,87 мс | 8/400 |

Полный warm путь: свежий E5 → переставленные 20 карточек → Nano → ID; i7-13700H, шесть Torch threads, по одному логическому потоку на P-core, E5 spinning выключен, тот же 177-объектный независимый каталог. Распознавание речи, загрузка и первоначальная индексация исключены. Прогоны проведены в прямом и обратном порядке. Проверены все 800 ID относительно CPU-оценки, максимум разницы вероятностей 2,24×10⁻⁶; повторно рассчитаны counts, суммы этапов, quantiles и hashes.

98,5% измеренных ответов быстрее 500 мс, но максимальная задержка около 884 мс. Ранее короткая проба Nano дала около 269 мс медианы; она измеряла 12 запросов, и этот полный замер не подменяет её условия. Веса те же, причина временной разницы не установлена. У RuModernBERT прежние два полных прогона дали 118/148 мс медианы и максимум 241 мс; такие измерения не гарантируют любой будущей нагрузки.

## Последние веса: отдельная диагностика качества

Последний фиксированный checkpoint 426 проверен на всех тех же 800 представлениях. Это оценка accuracy отдельно от NLL; он не выбирается по этим известным результатам задним числом.

| Сценарий | До / selected 0 | Последние 426 |
| --- | ---: | ---: |
| Real basic / 50 | 44 | 42 |
| Real difficult / 50 | 35 | 35 |
| Real ASR / 50 | 34 | 34 |
| Synthetic basic / 50 | 42 | 43 |
| Synthetic difficult / 50 | 36 | 37 |
| Synthetic ASR / 50 | 38 | 38 |
| Transfer basic / 50 | 46 | 47 |
| Transfer difficult / 50 | 38 | 38 |
| Independent clean / 200 | 166 | 168 |
| Independent ASR / 200 | 163 | 168 |
| Среднее десяти сценариев | **79,05%** | **79,60%** |

Обычная доля правильных ответов: 642/800 → 650/800 (80,25% → 81,25%); среднее десяти сценариев 79,05% → 79,60%, только +0,55 п.п. На текущем real-каталоге 113/150 → 111/150 (75,33% → 74,00%). На independent400 — 329/400 → 336/400 (82,25% → 84,00%). Последние веса исправляют 21 прежнюю ошибку, но теряют 13 прежних успехов; все 150 финальных GPU validation ID совпадают с CPU, максимум разницы вероятностей 2,85×10⁻⁶. Counts, источник весов, входы, softmax/ID mapping и NLL повторно проверены.

По первоначальному правилу NLL по-прежнему выбран шаг 0. Малый прирост accuracy на одном известном наборе и одном seed, с ухудшением текущего каталога, не является устойчиво подтверждённым улучшением. Этот вариант продолжения я бы не продвигал; абсолютный предел Nano этим не установлен.

Полный итог с hashes: `artifacts/kaggle/nano-continuation-evaluation-v1/comparison.json`; основной аудит `artifacts/kaggle/nano-continuation-final-audit.json`; последний диагностический аудит `artifacts/kaggle/nano-continuation-evaluation-v1/last-diagnostic-cpu-audit.json`. Последние веса сохранены отдельно, исходные файлы и выбранная модель сохранены. Дополнительных GPU-проб и переключения GUI нет.

В приложение новые веса не подключены; выбор финальной модели остаётся отдельным решением.
