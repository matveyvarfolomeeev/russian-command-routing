# Архитектура

Каталог, поиск и открытие не зависят от Qt. Интерфейс — клиент этих модулей, а экспериментам доступны те же данные и постоянные ID.

~~~mermaid
flowchart LR
    UI["QML: поиск, каталог, настройки"] --> C["Controller: Qt-адаптер"]
    C --> J["Jobs: фоновые задачи"]
    J --> D["Discovery: источники Windows"]
    D --> DB["Catalog: SQLite"]
    C --> DB
    C --> F["Search: текстовый фильтр"]
    C --> L["Launch: открыть по ID"]
    L --> DB
    C --> A["Recorder: аудио в памяти"]
    A --> S["Speech: Groq ASR"]
    S --> C
    CLI["CLI / Python-эксперимент"] --> DB
    DB --> SNAP["Полный каталог для модели"]
~~~

## Каталог

Catalog открывает короткоживущие соединения SQLite: объект можно использовать из фоновой задачи без передачи соединения между потоками. Обновление источников выполняется одной транзакцией.

В objects хранятся ID, идентичность запуска и JSON записи. sources связывает источники с объектами. settings содержит параметры приложения. Версия схемы — 4; версии 1–3 автоматически мигрируют, неизвестная версия отклоняется вместо изменения чужой базы. Обновление версии назначает один фоновый скан для применения новых метаданных и добавления папок. При объединении дублей сохраняются ID отредактированной записи, пользовательские поля, избранное и отключение; все ссылки источников переносятся на неё. Неиспользуемые автоматические дубли из старых сканов удаляются; пользовательские правки переносятся при однозначном совпадении команды или сохраняются отдельно.

merge_scan снимает доступность только у записей успешно прочитанного источника. Сбой источника оставляет прежние записи. Пользовательские изменения помечаются как overrides: новые метаданные не затирают описания, названия и альтернативные названия, включая намеренно пустое описание.

Дедупликация использует разрешённую цель ярлыка, аргументы и рабочую папку. Для непрозрачных AppID и GUID путей Windows Shell дополнительно сообщает цель и аргументы зарегистрированного приложения. Такая запись сопоставляется только с однозначной командой ярлыка; при нескольких рабочих каталогах остаётся отдельной. Для MSI ярлыков реальные установленные пути запрашиваются через MsiGetShortcutTargetW/MsiGetComponentPathW без установки или восстановления компонентов. Для открытия папок и документов рабочий каталог ярлыка не входит в ключ. Название само по себе не является ключом. Разные профили и параметры сохраняются отдельно. Существующий ярлык сохраняется как способ открытия, когда другой источник описывает ту же цель. Классификатор служебных действий исключает деинсталляторы до записи в каталог.

Discovery собирает пять источников: два меню «Пуск», приложения Windows, стандартные пользовательские папки и папки проектов. Системные папки определяются через специальные папки Windows и Shell, поэтому перенесённые «Загрузки» и OneDrive пути сохраняются. Корни проектов берутся из settings.folder_roots; CLI scan --folder-root сохраняет их, GUI использует при каждом обновлении. Сканируется только один уровень, без скрытых и служебных подпапок. Пути передаются помощнику как JSON в окружении и не вставляются в PowerShell код.

SQLite работает в WAL-режиме, чтобы чтение не ждало фонового обновления. Окно сразу получает сохранённые записи; после показа Controller.refreshIfStale запускает обновление только для устаревшего каталога. Полный успешный Windows-скан имеет отдельную дату last_successful_scan: ручное добавление файлов и сбой источника не делают кеш свежим. Интервал — 24 часа; проверка при старте и каждый час. Кнопка «Обновить» запускает сканирование независимо от возраста данных.

## Граница открытия

Вход из интерфейса — launch_by_id(catalog, object_id). Он получает объект из базы, проверяет доступность и вызывает Windows Shell либо subprocess со списком аргументов и shell=False.

Текст запроса и ответ будущей модели не становятся командами. Успешный вызов означает отправку команды, а не готовность окна. Реальные окна проверяются отдельным Windows-интеграционным сценарием.

## Фоновые задачи

Jobs содержит ограниченный QThreadPool и доставляет результат в GUI через сигналы Qt. В фоне работают сканирование, открытие, загрузка иконок, преобразование аудио и сетевое распознавание.

QML-провайдер иконок читает только готовый кеш. Windows-иконки извлекаются заранее в фоне; QML не дожидается Python-провайдера при уничтожении окна.

Recorder использует формат микрофона. После остановки исходный PCM превращается в 16-битный моно WAV в рабочей задаче. Аудио не пишется на диск. Для поздних ASR-ответов проверяется номер запроса; отмена или ручное изменение ввода делает старый результат неприменимым. Отмена результата не гарантирует отмену уже отправленного запроса на стороне сервиса.

При выходе приложение останавливает запись, отменяет дальнейшую загрузку иконок и дожидается ограниченных фоновых задач. Уже отправленный HTTP-запрос может задержать завершение до своего таймаута.

## Окно и один экземпляр

Qt.Tool делает окно плавающим служебным окном; горячая клавиша и трей возвращают его. Настройки менеджера окон не изменяются. Сочетание по умолчанию — Ctrl+Shift+Space; пользовательское сохраняется. При вызове неактивное или свёрнутое окно восстанавливается и получает фокус, активное скрывается. Регистрация Windows имеет явный статус в настройках и журнале; после ошибки при старте выполняется одна повторная попытка.

QML использует общие Theme и компоненты полей, кнопок, списков выбора и флажков. Они разделяют цвета, отступы и состояния фокуса; поиск, каталог, редактор и настройки используют одинаковые размеры и правила сокращения длинного текста.

QLockFile защищает каталог данных от второго экземпляра GUI. Повторный запуск через QLocalSocket просит существующее окно показаться. Сообщение не содержит команд. Разные каталоги данных позволяют держать отдельный экспериментальный экземпляр; для него можно отключить горячую клавишу.

## Где подключать модель

Используйте Catalog.model_catalog() для полного набора включённых и доступных вариантов. Controller.results предназначен для экранного фильтра и не служит входом модели.

Сначала вызывайте модель из отдельного эксперимента и оценивайте выбранный ID. После проверки результатов добавляйте её вызов в Qt-контроллер. Discovery, SQLite и launch.py менять не требуется.

## Упаковка

JevLauncher.spec собирает QML и ресурсы вместе с Python/Qt. Qt в Windows использует системную ICU. Рецепт исключает чужие ICU DLL из PATH: например, Poppler может поставлять библиотеку с тем же именем и несовместимыми экспортами.
