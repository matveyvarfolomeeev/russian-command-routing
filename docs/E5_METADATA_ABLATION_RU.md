# E5: что происходит без описаний приложений

Historical experiment record. Paths under `artifacts/` refer to local files; published predictions and ledgers are in [public evidence](../results/README.md).

8 октября 2026 пользователь спросил, является ли дообученная E5 самой быстрой, маленькой и качественной моделью и работает ли она без описаний. Проверен уже выбранный E5 checkpoint шага 142, без обучения и нового выбора весов. Все прежние 800 запросов, targets и 177 object_id каждого каталога сохранены.

## Быстрота, размер и качество — разные показатели

E5-only выполняет один query encoder и cosine по заранее вычисленным карточкам. Поэтому её warm latency около 14–15 мс — один из самых быстрых проверенных нейронных путей проекта. Исходная E5 была столь же быстрой, около 13–15 мс. Дообучение улучшило качество, не сократило архитектуру. Эти числа исключают ASR, загрузку и первоначальное индексирование; прежние timings других моделей имели свои условия/объёмы.

| Модель | Параметры | FP32 model.safetensors |
| --- | ---: | ---: |
| E5-small encoder | 117 653 760 | 470 637 416 байт, примерно 470 МБ |
| RuBERT-tiny2 + голова | 29 194 081 | 116 782 884 байта, примерно 117 МБ |
| RuModernBERT reranker | 34 539 649 | 138 166 484 байта, примерно 138 МБ |

Слово small — обозначение варианта семейства, а не утверждение, что это самая маленькая модель в нашем пуле. E5 не минимальна по весам; постоянная память процесса отдельно здесь не измерена. По сохранённому старому STT Kev даёт 87%, E5 82%, Laya 80%; macro10 94,95%, 89,40%, 87,85%. Значит, E5 — сильный компромисс качества и задержки, а Kev остаётся лидером этих измерений качества. [Сводка](FINAL_MODEL_COMPARISON_RU.md).

## Что видит E5

Карточка строится как `passage: название. тип. описание. aliases`. Пустые поля пропускаются. Encoder превращает текст в 384-мерный нормализованный вектор, отдельно кодирует `query: запрос`, затем программа сортирует cosine scores и сопоставляет карточки с ID. Отдельная decision-голова и генерация ответа в этом пути отсутствуют. Пути запуска, executable, AppID, содержимое приложения и значки не входят в текст E5.

При запросе с явным названием модель может сопоставить его с названием карточки. При запросе по назначению имя известной программы иногда даёт нужную связь из pretrained знаний. Но у неизвестного приложения с условным именем сведения о назначении могут отсутствовать полностью. Если карточка содержит только «Zuro. Приложение», запрос «открой редактор фотографий» не сообщает, почему нужно предпочесть Zuro другим неизвестным именам. Aliases способны сохранить часть таких сведений.

## Два вмешательства в карточки

Удалены поля только у объектов kind=app, всех 139 приложений каждого каталога. Описания и aliases файлов/папок сохранены. Тип, имя, порядок ID, запросы и labels не менялись. Для каждого варианта карточки заново закодированы теми же весами; старые embeddings не переиспользованы. Полный контроль взят из проверенного CPU800 того же SHA.

1. **Без app description:** описание пустое, прежние aliases сохранены.
2. **Только app name + kind:** пустые description и aliases приложений.

## Результат по всему known800

| Карточки приложений | Macro10 | Правильных /800 | Шумный STT: среднее | Real STT /50 | Synthetic STT /50 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Исходные метаданные | **89,40%** | **735** | **82%** | **39 — 78%** | **43 — 86%** |
| Без описаний, aliases сохранены | 67,70% | 538 | 77% | 37 — 74% | 40 — 80% |
| Название + тип | 62,90% | 514 | 68% | 35 — 70% | 33 — 66% |

Macro10 даёт сценариям одинаковый вес. Обычная доля всех строк составляет 91,875%, 67,25% и 64,25%; эти усреднения различаются. На вопрос об отсутствии описаний относится второй вариант; 70% real STT относится к третьему, где также удалены aliases.

Общая сводка содержит 250 запросов к файлам/папкам, их карточки сохранили сведения. Если выделить **550 запросов к приложениям**, среднее по десяти сценариям **91,27% → 59,73% → 51,73%**, counts **511 → 313 → 289 из 550**. Даже неизменные карточки файлов/папок могут получить иной ранг из-за изменения app-дистракторов.

| Сценарий | Полные карточки | Без описаний | Название + тип |
| --- | ---: | ---: | ---: |
| Real basic /50 | 45 | 44 | 42 |
| Real difficult /50 | 39 | 37 | 35 |
| Synthetic basic /50 | 48 | 44 | 38 |
| Synthetic difficult /50 | 41 | 37 | 32 |
| Третий вымышленный каталог: basic /50 | 50 | 20 | 20 |
| Третий вымышленный каталог: difficult /50 | 46 | 13 | 13 |
| Independent clean /200 | 193 | 135 | 135 |
| Independent ASR /200 | 191 | 131 | 131 |

В independent aliases исходно нет, поэтому два удаления эквивалентны. В real каталогах описания уже отсутствовали у 73 из 139 приложений, aliases есть лишь у 12. Поэтому удаление оставшихся описаний снижает итог меньше, чем в полностью описанных вымышленных каталогах. Этот опыт не отделяет влияние известных брендов, типов запросов и разного числа alias; их вклад по отдельности не измерен.

В сравнении с полными карточками удаление только описаний исправило 5 ошибок и потеряло 202 правильных ответа; удаление также aliases исправило 4 и потеряло 225. Это оценка фиксированной обученной модели при изменении входов. Модель специально на name-only режиме не дообучали: возможность улучшить такой режим отдельным рецептом остаётся непроверенной.

## Проверки и файлы

Для обоих вариантов по 800 прогнозов восстановлены правильность, full177 ranking, target rank, top20, softmax, paired counts и macro/micro. Проверено, что карточки файлов/папок не изменились, веса имеют прежний SHA и все исходные fingerprints совпали. Ruff прошёл. Нет optimizer updates, checkpoint selection, Kaggle upload или изменения приложения. Старый sealed test не открыт; это дополнительная диагностика уже известного набора.
