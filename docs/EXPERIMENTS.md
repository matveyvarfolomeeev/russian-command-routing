# Основа для экспериментов

В репозитории нет decision model или ML-бенчмарка. Уже работают каталог, экспорт и простой фильтр для подготовки данных и сравнения будущих моделей.

## Снимок каталога

Обновите каталог в приложении и заполните нужные описания. На время эксперимента экспортируйте полный набор:

~~~powershell
.\.venv\Scripts\jev-catalog.exe export --output artifacts\catalog-v1.json
~~~

Формат:

~~~json
{
  "schema_version": 1,
  "catalog_hash": "sha256 от канонического списка objects",
  "objects": [
    {
      "object_id": "постоянный ID",
      "name": "Редактор",
      "kind": "app",
      "description": "Редактор кода",
      "aliases": ["вскод"]
    }
  ]
}
~~~

Хеш учитывает ID, названия, описания, типы, альтернативные названия и состав каталога. Изменение этих полей меняет хеш. Одинаковый снимок позволяет сравнивать модели на одинаковых вариантах.

Экспорт не содержит путь запуска, аргументы, API-ключ или иконку. Названия и описания всё равно могут быть личными данными; снимки сохраняются в игнорируемом каталоге artifacts.

ID устойчив внутри каталога при обновлении. На другом компьютере или в заново созданной базе ID могут отличаться: переносите в эксперимент снимок, а не заново собирайте варианты для каждого метода.

## Работа без интерфейса

~~~python
from jev_launcher.catalog import Catalog
from jev_launcher.search import filter_catalog

catalog = Catalog()  # Или Catalog("artifacts/sandbox/catalog.sqlite3")
query = "редактор кода"

full_candidates = catalog.model_catalog()
matches = filter_catalog(catalog.items(), query)

print("Вариантов для модели:", len(full_candidates))
print("Совпадения текстового фильтра:", [item.object_id for item in matches])
~~~

Код ничего не открывает. Будущей decision model передавайте full_candidates целиком, независимо от matches. Фильтр — инженерная база сравнения, которая не заявляет понимание свободного текста.

Для отдельного каталога:

~~~powershell
.\.venv\Scripts\jev-catalog.exe --db artifacts\sandbox\catalog.sqlite3 scan
.\.venv\Scripts\jev-catalog.exe --db artifacts\sandbox\catalog.sqlite3 add "D:\My Project"
.\.venv\Scripts\jev-catalog.exe --db artifacts\sandbox\catalog.sqlite3 search "project"
~~~

CLI поддерживает scan, list, export, search и add. Он не содержит команды автоматического открытия по результату поиска.

## Запросы и разметка

Сохраняйте запросы отдельно от снимка. Пример будущей строки разметки:

~~~json
{"query": "открой программу для кода", "expected_action": "open", "expected_object_id": "ID из снимка", "input_type": "text", "group_id": "editor-paraphrases"}
~~~

Для отсутствующего объекта и неоднозначного запроса используйте not_found и clarify. Нажатие пользователя не считается автоматически правильным ответом.

Держите вместе связанные перефразы, голосовой пример и его ASR-текст. Чистый текст и распознанный текст оценивайте отдельно. Зафиксируйте каталог, разметку и разбиение до сравнения моделей.

## Граница эксперимента

Оценка модели возвращает ID, вероятности или отказ от выбора. Не вызывайте launch_by_id во время измерения качества. Проверяйте точность выбора, ложные открытия, уточнения, задержку и калибровку на фиксированной разметке.

После эксперимента выбранный ID можно передать существующему launch.py. Пути и способы открытия остаются в инженерной части. Отдельный агент, сервер или система плагинов для этого не нужны.
